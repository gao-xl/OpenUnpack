# 1–5 任务负载与工程优化报告

日期：2026-10-15。对应方案：[执行方案](load-optimization-plan-2026-10-15.md)。本轮按用户明确要求将上限提高到 **5 个活跃任务**；默认保持 1。当前生产链仍为 React/Tauri → Core Coordinator → Worker → Engine。

## 修复结果与边界

| 项目 | 原问题与影响 | 本轮处理 |
|---|---|---|
| 五并发 | 设置、运行循环、物理盘仲裁及 UI 上限为 4，无法真正运行 5 项 | Rust 协议常量及 UI 常量均为 5，校验拒绝 0/6；调度及运行循环引用常量；契约门禁检查两端一致 |
| 自动线程 | 每个 Worker 的自动线程数都可使用全部逻辑核，多个任务容易争抢 CPU | 支持线程参数的 7-Zip 解压按 `逻辑核 / 配置并发` 分配，范围 1–64；显式手动值保留。请求发出前使用当前并发，避免队列旧选项失效 |
| 暂停竞态 | 任务领取持久化过程中，暂停可能先返回，随后任务才进入运行 | 暂停与领取共享命令门闩；返回后仅允许此前已经领取的任务继续 |
| 缓存设备遗漏 | 尚未建立工作区的任务，没有登记/检查候选缓存盘，两个任务可能同时占用同一机械盘 | 仲裁包含计划缓存端点；HDD 和未知拓扑保持排他；源、目标、缓存映射到同一物理盘时每任务只计一次；本次仲裁保留较严格的设备分类 |
| 缓存展示覆盖 | A/B 任务回报进度时覆盖同一个累计值，3170 字节示例只显示 1120 | 按任务保存工作区贡献，严格匹配请求/操作/代际后合计；阶段结束校准本任务；全量校准避开活跃请求；过期扫描及其错误不得覆盖新进度；有效扫描报错时也同步已清理账项后的总数 |
| 配额安全 | 展示估算不能成为磁盘准入依据 | 保留真实目录扫描、共享预留和未知大小归档的独占预算机制；本轮展示优化没有替换这些检查 |
| 构建重复 | 安装构建前重复编译 UI/Host，增加耗时和旧文件混入判断难度 | prepare 支持跳过 UI；安装分支由 Tauri 唯一负责新 UI 和最终 Host；纯便携分支各编译一次，最终 Host 完成后才冻结便携内容 |
| PDB 重名 | Host lib/bin 同名造成调试符号目标碰撞 | lib 改为 `openunpack_desktop_lib`；产品、包和可执行文件名保持原值 |
| 校验镜像 | Infrastructure 纯相对路径策略缺少 Core 的 128 层限制，未来迁移可能降低保护 | 补齐限制、四项回归和第五项镜像门禁；负向自检检测比较符、深度常量和保留标记漂移 |
| 测试安全 | 旧物理盘测试使用传入根下固定目录名并删除 | 每轮新建 UUID 归属目录，仅在成功且归属核对后清理；失败保留，绝不删除传入根 |
| 架构计划 | Core 退役计划把 toolbox 依赖归结为少数纯函数，低估安全 IO 迁移 | 明确 DirectoryGuard/LockedEntry 等 S06 身份与权限前置条件；本轮不切换生产入口 |

自动线程参数目前实际作用于支持 `mt` 的 7-Zip 解压处理器。Inspect/Probe、托管 LZ4 不能据此宣称受同样控制。每个 Worker 原有 50% CPU / 4 GiB 提交内存限制是**进程级**限制，不能相加解释为整个应用的统一预算；5 并发也不表示任意归档都适合开到 5。

独立静态复查补获一项 P2 显示一致性问题：删除 A 的记录后，B 的有效目录扫描报错，使分项已变更而总数未同步。确定性回归复现应为 100 却仍显示 200。最终修复在返回原始扫描错误前重算总数；可见状态更新器原有机制仍负责推进修订号，保留错误和订阅可见性。复查未发现该补丁新增锁循环，配额准入仍独立于显示统计。

## 测量方法

- 本机现查：i5-8500T，6 核/6 逻辑处理器，约 16 GiB 内存；C: 三星 NVMe SSD（物理盘 1），D: 东芝 MQ04ABD200 SATA HDD（物理盘 0），NTFS。
- 固定 10 个独立合成归档，各档总工作量相同。SSD 主矩阵为每任务一个 64 MiB 大文件及 128 个小文件；严格交付校验开启，完成后再逐文件 SHA-256、路径清单及原归档摘要核对。准备归档和事后核对不计入吞吐窗口。
- 单独使用优化编译的生产 Coordinator 测试入口和冻结 Release Worker；测量期间不并行构建。早期 Debug 诊断因未优化校验耗时偏大而中止，其结果不用于性能结论。
- Native Windows 计数器按 100 ms 采样，Worker 身份为 PID + 创建时间，保留进程句柄读取最终 CPU/IO。内存为同一采样时刻 host + 已观察 Worker 的总量；CPU 按整机 6 核归一化。I/O 是进程计数，包含管道/设备，不等于物理盘吞吐。
- 100 ms 会漏掉更短的进程及瞬时峰值；记录采样错误/未及时打开的候选。不清系统缓存、不调整电源，也不声称机器完全无其他后台负载。单轮结果不是统计显著的长期性能承诺。
- HDD 源、输出与测试任务库位于本轮 HDD 私有目录，缓存模式使用另一物理 SSD；该任务库布局与日常 AppData 位于 SSD 的安装不同。绝对速度不能直接代入所有用户场景。
- 暂停/取消另用每任务 128 MiB + 1024 小文件，确保观察到真实输出进度；暂停不挂起正在执行的原生线程。单项取消在仅有一个活跃任务时精确归属目标 Worker；批停核对当时实际存在的全部 Worker，退出与终态门限均为 5 秒。

控制夹具首轮曾错误要求取消后工作区统计为零，导致验收失败；生产行为是保留部分工作区供重试。夹具改为核对归属、实际保留量与显示一致，并完整重跑；没有通过删除重试数据或放宽退出门限来让测试通过。原失败日志保留为 `after-controls-first-fixture-error.log`。
