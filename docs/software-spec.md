# OpenUnpack 软件规范

版本：0.2 讨论稿 · 日期：2026-10-07 · 状态：只设计规范，代码开发已停止

项目名暂定 OpenUnpack，中文工作名“解压工坊”。本文件描述期望行为，不代表已有功能通过验收。已有早期代码文件保留，不继续修改；后续只有用户明确恢复开发后才进入实现。

## 1. 产品定义

面向 Windows 用户的独立、离线、开源桌面软件。把用户已有的解压密码整理成密码库，批量处理压缩文件，自动尝试已保存的密码，记住成功关联，并通过可选 SSD 工作缓存改善机械硬盘来源的处理效率。

核心场景：机械硬盘保存大量 ZIP / 7z / RAR，密码分散在不同来源；用户把文件或文件夹拖入软件，选择密码范围与输出位置，得到逐任务明确的结果。

产品原则：

- 原始压缩文件默认保留；完整成功前不将临时输出显示为成品。
- 每个密码只按用户提供的有限候选尝试，不生成密码、不进行暴力穷举。
- 密码与文件默认留在本机，无账户注册、云查询或遥测。
- 每个阶段、错误和可恢复操作可解释；通用失败不能一律标为密码错误。
- 采用独立名称、界面和实现；不复用参考软件的代码、品牌资产、私有数据库或组件。

## 4. 主界面与操作流程

界面分为“批量解压”“密码库”“处理记录”“设置与备份”。首屏展示真实空队列和添加方法，不预填演示任务。

### 4.1 批量解压

1. 拖入文件、多个文件或文件夹；也可用“添加文件”“添加文件夹”。
2. 扫描后显示任务数、分卷数、跳过项及扫描错误；明确这是发现结果，不是完整性验证。
3. 选择输出位置、冲突规则、密码分组、SSD 缓存、是否展开内包及写回验证模式。
4. 点击开始；显示每项阶段、进度、候选已试数量和总结果。
5. 完成后可打开输出位置、重试失败/缺密码项、清空已完成项。

任务表字段：压缩包名称、类型、压缩大小、分卷数量、当前阶段、阶段进度、结果/原因、输出位置。密码只显示候选序号或用户自定名称，口令字段不出现在表格、日志或异常对话框。

运行期间冻结队列和任务配置，密码库编辑暂不可用；采用开始时的候选快照。点击关闭窗口时，提供“继续运行”或“取消并等待清理后退出”。

### 4.2 密码库

列表字段：名称、分组、口令掩码、备注、启用状态、成功次数、最近成功时间。搜索名称、分组和备注；搜索口令本身不作为默认行为。

新增和编辑使用遮盖口令控件。临时查看必须由用户显式触发；离开编辑区或页面后重新遮盖。复制口令是显式操作，建议 30 秒后只在剪贴板仍是软件写入内容时清除。

### 4.3 设置与备份

显示实际用户数据目录、解压引擎状态/版本、SSD 缓存位置及容量、备份/恢复入口。缺失引擎给出可执行的获取指引；不能留下无响应的“开始”按钮。

## 5. 密码管理规范

### PW-01 记录与分组

每条密码包含稳定 ID、名称、口令、分组集合、备注、启用状态、创建时间、成功次数和最近成功时间。建议同一口令在库内只保存一份，允许关联多个分组。停用对所有分组生效。

口令按 Unicode 原文比较，大小写与前后空格有意义，不自动 trim、不做大小写折叠。首版建议支持单行口令，拒绝 NUL/CR/LF，并在录入时说明限制；TXT 与 TSV 也不能隐式转换口令。

### PW-02 导入

- TXT：默认 UTF-8/UTF-8 BOM，一行一个密码；空行跳过，空格行不等同空行。非 UTF-8 需明确选择编码后预览，不能静默猜测。
- TSV：明确格式标记与四列“名称、密码、分组、备注”；列分隔符不会被当作普通口令字符。
- 导入先预览新增、重复、格式错误及目标分组，不向错误消息回显口令。
- 默认保留已有名称与备注，合并新增分组；不同名称/备注的覆盖须在预览中显式选择。
- 提交为一个原子操作，任何校验失败均不产生半个导入结果。
- 旧软件迁移使用用户显式导出的文本文件，不自动读取原软件数据库。

### PW-03 尝试范围与顺序

先尝试无密码打开/解压；需要口令时，仅使用所选分组中的启用密码：

1. 当前归档内容已关联的成功密码。
2. 内包可优先尝试本次外层已验证的成功密码，但必须属于当前分组且仍启用。
3. 其他候选按成功次数降序、最近成功时间降序排列；相同条件保持稳定顺序。

即使曾关联成功，停用密码或不属于当前分组的密码也不能越过范围限制。相同口令只试一次。候选耗尽进入“需要密码”，允许用户补充密码后重试。

不对每个候选执行一次完整测试后再完整解压。可利用格式支持的头部验证做轻量试探，或直接解压到候选暂存目录；完整解压成功的结果复用，不再次重解。轻量试探不能代替最终校验；固实归档和没有可靠密码验证头的格式可能仍要解码较大范围，不能承诺每个错误口令都能瞬间排除。

### PW-04 成功记忆

必须当前归档节点全部条目完成解压、引擎完整性检查且结果成功交付，才更新密码成功记录。嵌套任务按节点区分内外层关联；最终写回失败不把未交付任务标为完成。仅能读取文件名或只解出部分内容均不算密码成功。写回验证按所选模式执行，不要求标准模式做完整目标回读。

关联以整组分卷的内容指纹为依据，不以文件名作为唯一标识；改名仍可复用，内容变化需要重新确认。开启源包缓存时，在复制过程中计算每卷摘要，避免额外完整读取机械硬盘。没有可靠指纹时允许正常解压，但不能记入错误关联。

删除密码时清理其关联；历史保留脱敏结果，不保留已删除口令。

### PW-05 加密与备份

用户已确认本地库由当前 Windows 账户自动解锁、加密保存；加密备份单独使用用户设置的口令，支持换电脑恢复。此方式不能阻止同一 Windows 用户下的恶意程序读取运行中数据。

备份不提供默认明文导出。恢复先解密、校验、预览，默认合并条目；首版不提供静默替换整个密码库。错误口令、篡改、版本不兼容或文件损坏均不得改变当前库。

保存采用临时文件和原子替换，保留上一版有效文件。库读取失败时禁止用空库覆盖，提供数据位置、备份恢复及重新尝试入口。

## 6. 扫描、格式与输出规范

### AR-01 发现压缩文件

默认递归扫描选择的文件夹；只把支持格式加入队列。重复拖入同一规范路径不产生重复任务；不同路径的同内容包保留独立任务，后续可提示内容重复。

访问被拒绝、不可读目录和不支持文件分别计数。不跟随目录链接，避免循环和越界扫描。扫描完成前可取消，不改变源文件。

### AR-02 分卷

一组分卷只有一个任务，列出组成文件、顺序和总大小。从首卷开始，直接拖入中间卷时尝试定位整组；找不到首卷明确报告缺卷。除命名与序号连续性检查外，还需解压引擎验证完整性，不能凭扩展名宣称完整。

SSD 缓存以整组分卷为单位复制；任何卷读取失败或发生变化使该次缓存失效，不混用旧、新卷。

### AR-03 输出位置与冲突

默认在压缩包旁边创建独立目录，支持选择统一目标根目录。剥离完整的归档/分卷后缀形成目录名；同名包从不同来源入队时仍按同一冲突规则处理。

首版只提供“新建名称（默认）”和“跳过”。例如资料 → 资料 (1)。既有目录和文件不被覆盖。发布前再次检查名称，处理期间外部创建同名目录也必须遵守规则。

### AR-04 安全写入与校验

拒绝绝对路径、路径穿越、设备路径、备用数据流、链接/重解析点、大小写冲突条目以及文件/目录结构冲突。所有条目约束在当前任务暂存根目录内。

解压时保持引擎内建完整性检查开启，并读取每条目的校验结果；不默认先做一次全包测试，再重复解压。仅列表/路径预检不算全包测试。对没有内建校验码的条目应记录实际能力，不能声称通过了不存在的 CRC 检查。

条目数、预计解压大小和实际写入累计限制都通过后才发布。未知解压大小不能跳过累计限制。首版建议单个根任务（包含所有内层）累计最多 100000 条目、100 GiB 解压数据；释放中间文件不会重置累计额度。

普通模式：解到目标卷的独立临时目录，成功后在该卷内改名发布。SSD 模式：按第 7 节执行跨卷写回。空归档可完成并给出“没有内容”，不能因此推断某个口令有效。

### AR-05 双重压缩与输出结构

“自动展开内包”为可选开关。首版建议最多解开 2 层（原始外包计第 1 层），更多层只保留压缩文件并标记“达到层数限制”。按允许格式和引擎识别确认内包，不能把 DOCX/XLSX/JAR/APK 等基于 ZIP 的文档或应用容器自动当作普通内包展开。

启用 SSD 时，外层解到 SSD，内层也在同一工作目录下解开；构建最终目录树后才写回。中间压缩文件不先写回机械硬盘再重新读取。普通文件、目录和说明文件原样保留；成功内包以同位置的独立目录替代，默认不把内容全部扁平合并。

例：外包包含 README.txt、资料/a.zip、b.7z，最终交付 README.txt、资料/a/…、b/…。若原来已有资料/a/，新展开目录使用资料/a (1)/。用户可选择额外保留内层压缩文件，该选择会增加最终输出大小。

内外层密码独立匹配、独立关联；外层成功不代表内层成功。成功完成并通过检查后，可释放仅由软件生成、可从原始外包重建的中间文件；用户原始外包及其分卷始终保留。

内包缺密码或损坏时，保留该内包和已完成内容，任务进入“内层待处理”，不给出全部成功结果。用户可补密码后只重试该内包，也可显式选择“交付部分结果”或“取消并清理”。部分结果必须保留未成功展开的内包、标出未完成项；不得静默丢弃。保留工作区计入 SSD 配额，资源不足时暂停，不能无限占用缓存。

## 7. SSD 工作缓存规范

### 7.1 目的与模式

面向机械硬盘来源，减少重复读源包及机械硬盘上的解压小文件写入。用户选择真实 SSD 上的目录，软件展示所选卷；不能凭目录名称判定 SSD。

SSD 工作目录默认关闭；启用后，外层与内层都在 SSD 暂存解压。源包是否先复制到 SSD 单独配置，建议有“按需（默认）/始终复制/不复制”三种选择：关联密码命中或候选很少时可直接读取机械硬盘外包并解到 SSD；需反复尝试密码或输入频繁随机读取时优先缓存整个源包/分卷组。切换到完整源缓存前清理失败候选产物并重新预留空间。阈值需实测后定稿，不能保证任意格式外包只读一遍。

双重压缩时，可跳过不必要的原始外包副本，但内包和展开结果仍保留在 SSD；这与关闭 SSD 工作目录不同。SSD 空间不足不会静默改变最终输出配置。

缓存是任务工作目录，不是系统级硬盘加速器，不需要磁盘驱动。首版完成后清理，不承诺跨任务命中；持久化输入缓存复用属于 P1。

### SSD-01 状态管线

等待 → 源包缓存（按需）→ 外层解压及同步校验 → 内包发现与独立密码匹配 → 内层解压及同步校验 → 最终目录树确认 → 写回目标临时目录并做流式比对 → 完整回读（仅严格模式）→ 目标卷内改名发布 → 清理本任务缓存 → 完成。

任一阶段出错应显示具体阶段，禁止把“SSD 中解完”显示为最终完成。阶段进度、已处理字节和耗时分别显示；总耗时包括源包复制和最终写回。

### SSD-02 配额与剩余空间

建议默认配额 20 GiB，用户可调整；建议最小剩余空间为 max(2 GiB, 所选缓存卷容量的 5%)，阈值可配置。这里的 GiB 为 1024³ 字节，界面使用统一单位。

预算包括启用时的外包副本/全部分卷、未释放的内层压缩文件、最终内容、当前候选暂存和软件的遗留工作目录；最终目标磁盘需要另行容纳整份输出。外层提取的大小不能代表双重压缩后的最终大小。每发现新内包重新估算，未知时依实际写入累计和实时剩余空间检查。内包成功后释放可重建中间文件，避免所有层数据同时保留。

单个任务大于配额：明确标记“缓存容量不足”，允许用户增大配额、切换目录或关闭缓存后重试；其他较小任务可继续。整个缓存盘低于保留空间或不可用：暂停队列并提示处理，不静默更换缓存或改成直接解压。

### SSD-03 一致性与发布

开启源包复制时，在必要的复制读取中计算每卷 SHA-256，读取期间限制共享写入并检查源状态变化。摘要用于内容标识，不能凭对复制源流计算了一次摘要，就宣称缓存目标或机械硬盘已完成回读验证。源文件变化、卷序变化、缺卷或可见摘要变化使缓存失效。未复制源包时，按实际读取/格式元数据能力建立关联，不能为快速路径虚构完整内容指纹。

写回先进入最终目标卷的独立临时目录；按 SSD-06 所选验证模式完成检查，关闭句柄后再在目标卷内改名发布。标准模式没有完整读回机械硬盘，不能显示“目标内容已完整回读验证”。跨卷复制本身没有原子性，不能直接复制进已有最终目录。

源包、分卷和已完成输出均保留。复制/解压期间 SSD 移除、磁盘满、权限变化或目标断开均不产生“完成”结果。

### SSD-04 清理、取消与异常退出

每个工作目录包含软件标记、任务 ID、阶段和来源摘要；不含明文密码。清理仅限本软件创建且与任务清单一致的目录，不能只凭相似名称删除。

成功后清理缓存；一般失败或取消后关闭所有句柄，再清理尚未发布的缓存和目标临时目录。内层待处理或写回失败时，可保留已验证的 SSD 工作区供用户补密码/重试写回，避免重解两层；保留状态、占用和清理入口必须可见。再次写回前核对工作区清单与文件状态，异常退出后的未验证半成品不能直接复用。清理失败保留明确位置，界面显示“输出已完成，缓存待清理”或“失败，临时数据待清理”，避免混淆输出成功和清理成功。

重启识别遗留任务，提供“清理临时数据”或“从头重试”；只有带完整成功记录且复核通过的最终工作区才能选择重试写回。首版不从未经复核的解压半成品续写。禁止自动删除来源；既有输出不能在恢复清理时被识别成缓存。

缓存可能短暂包含解压后的明文文件，应限制目录访问到当前用户；它不由密码库加密机制自动保护，也不承诺 SSD 删除后不可恢复。设置页说明这一点，用户可选择受系统磁盘加密保护的位置。

### SSD-05 性能验收

在相同源包、密码候选、输出位置和引擎版本下，对比关闭缓存与开启缓存的端到端总耗时。分别记录复制、口令尝试、解压、校验、写回、清理时间，最大 SSD 占用与写入量。

覆盖三类场景：少量大文件、海量小文件、较多候选密码。区分冷读取与操作系统已有文件缓存的重复运行。首版单任务顺序执行，避免同时读取同一机械硬盘增加寻道。

不承诺固定倍数加速。CPU 解压、单次顺序读取以及最终机械硬盘写回可能占主导，开启缓存也可能更慢；性能结果必须包含这些情况。

性能矩阵增加双层套包：对比“每层都写机械硬盘”和“全部层在 SSD，最终写回一次”，记录机械硬盘总读写量、完整回读额外耗时、各层解码时间以及峰值 SSD 占用。普通校验不增加完整机械硬盘读取；摘要计算仍有 CPU 开销，不能计为零成本。

### SSD-06 校验合并与验证等级

默认采用“标准流式验证”，重要资料按任务选择“完整回读验证”。安全路径、大小/数量限制和引擎内建完整性检查在两种模式中都保留，不提供关闭这些检查来加速的选项。

| 模式 | 解压阶段 | 写回阶段 | 额外磁盘读取 | 完成结果 |
|---|---|---|---|---|
| 标准流式验证（推荐） | 引擎边解码边检查内建 CRC/MAC 等；在最终文件输出流中计算期望 SHA-256 | 从 SSD 复制最终文件时同步计算读取摘要并与期望值比对；检查完整写入、错误状态、文件数量与大小 | 无单独完整扫描 SSD；不完整回读 HDD | 写回完成，未做目标内容回读 |
| 完整回读验证 | 同标准模式，复用解压时已生成的摘要 | 写回后刷新并重新读取目标文件，逐文件 SHA-256 与期望值一致才发布 | 增加一次目标文件全量读取 | 写回完成，已通过完整逻辑回读 |

标准模式的流式比对验证从已校验解压内容到复制读取流的一致性，可以发现 SSD 中间内容变化；它不是机械硬盘最终存储内容的独立校验。只给复制源缓冲区计算摘要不能证明目标磁盘内容相同。

严格模式应尽量避免系统文件缓存把同一内存内容当作物理读回：目标刷新后使用适当的绕过缓存读取设计，并按设备/系统能力记录边界。即使刷新和逻辑回读成功，也不宣称绝对保证设备断电后的持久性。此限制需在验收中区分，不要求标准模式每写一小块就强制刷盘。

对大量小文件，按稳定目录顺序一次处理，限制目标机械硬盘并发；不在每层结束后再次扫描全目录算摘要。最终文件的期望摘要应在原有解压输出流中生成，比较摘要在原有复制读取流中生成；无法取得可靠期望摘要的路径应明确标记验证能力，不能假装比较通过。

示例时间仅用于解释设计：100 GiB 按 150 MiB/s 顺序读取约 11.4 分钟；大量小文件可能更慢。因此完整目标回读通常是额外开销的大项，不能靠更换摘要算法消除这一遍读取。

### 7.2 技术依据与边界

7-Zip 官方实现显示 ZIP 解码将输出 CRC 与归档记录比较，相关 AES 模式还检查认证码；7z 提取在写出数据时累计 CRC，在条目关闭时判定 CRC 错误。根据这些机制，本规范建议复用提取时的完整性结果，避免常规任务先完整 test 再重复 extract。不是所有格式/条目都一定含校验码。

资料：

- https://github.com/ip7z/7zip/blob/main/CPP/7zip/Archive/Zip/ZipHandler.cpp
- https://github.com/ip7z/7zip/blob/main/CPP/7zip/Archive/7z/7zExtract.cpp
- https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers

微软文档说明系统通常先缓冲文件写入，频繁强制刷新可能影响效率。因此把刷新与必要的发布检查安排在恰当阶段，并把刷新、逻辑读回和物理设备持久性分开描述。该设计尚未做真实 HDD/SSD 性能测试。

## 8. 任务状态、失败与重试

| 状态 | 对用户的含义 | 后续动作 |
|---|---|---|
| 等待 / 扫描中 | 尚未执行解压 | 可移除、取消扫描 |
| 复制缓存 / 内外层尝试密码 / 解压 / 流式比对 / 写回 / 完整回读 | 显示实际阶段和阶段进度；完整回读仅严格模式出现 | 可取消 |
| 完成 | 所选验证模式通过且最终发布成功；显示是否做完整回读 | 打开输出位置 |
| 内层待处理 / 部分结果 | 区分外层已完成与内包未完成，不计为全部成功 | 补密码、重试内层、显式交付部分结果或清理 |
| 完成，缓存待清理 | 输出有效，但临时目录未清理 | 显示位置、重试清理 |
| 需要密码 | 有限候选已耗尽，或缺少候选 | 补充密码、改变分组、重试 |
| 缺分卷 | 首卷/后续卷缺失或不可读 | 放齐分卷后重试 |
| 损坏 / 校验失败 | 数据损坏或不可验证 | 重新获取源包后重试 |
| 空间不足 / 路径无权限 | 明确缓存或最终目标阶段 | 更换路径/调整配额后重试 |
| 暂停，资源不可用 | 队列共享的磁盘不可用或低于阈值 | 恢复资源后继续 |
| 已跳过 | 输出目标已存在且选择跳过 | 可改策略后重新入队 |
| 已取消 | 原文件保留，当前任务未发布 | 清理后可从头重试 |

损坏的加密数据有时无法与密码错误完全区分，显示“密码不匹配或加密数据损坏”，不宣称已经确定是哪一种。普通单项失败不阻断其他任务；共享资源不可用采用显式暂停。

取消在读写检查点生效，界面立即进入“正在取消”，不承诺瞬间强杀原生引擎。已完成输出保留；当前未发布任务清理；后续任务不继续开始。

重试仅重跑失败、缺密码或取消的选中项，使用新的候选和配置快照，不重复提取已经完成项。

## 9. 数据、配置与历史

| 对象 | 必要数据 | 持久化规则 |
|---|---|---|
| PasswordEntry | ID、名称、口令、分组集合、备注、启用、统计 | 口令所在的整个库加密保存 |
| ArchiveMatch | 归档/分卷内容指纹、密码 ID | 与密码库一并保护，删除口令时清理 |
| Task | 来源路径/分卷、配置快照、阶段、结果、输出路径 | 任务清单无口令；路径可能敏感，应按用户数据保护 |
| CacheManifest | 软件标记、任务/内层节点 ID、目录、来源摘要、输出摘要、验证模式和阶段 | 不存口令，写入与阶段变更一致 |
| Settings | 输出规则、密码范围、缓存位置、配额 | 不含口令，配置失效有明确提示 |

存储位置与备份路径可以在设置页查看；单实例或数据目录级互斥防止并发覆盖。导入、编辑或保存失败不把界面中未落盘的数据假装为持久化成功。

## 10. 非功能规范

- 操作系统：Windows 10/11 x64；具体最低系统版本随框架定稿确认。
- 交互：简体中文优先，可调整窗口；建议最小 1000×680，适应 125%/150%/200% 缩放，长列表可滚动，键盘可访问主要操作。
- 响应：扫描、读写、密码尝试及备份加密在后台执行；UI 显示可取消状态，不因大文件阻塞。
- 可靠性：失败不损坏源文件和已有输出；从临时数据到成品有明确提交点。
- 资源：首版默认顺序处理一个归档；资源限制不随缓存开关失效。
- 隐私：默认无网络通信；仅用户显式获取/更新引擎时下载依赖。错误反馈和诊断包先脱敏，密码库和解压内容不纳入。
- 维护：应用与解压引擎版本分别可见；依赖可替换，格式测试矩阵随版本维护。
- 开源：应用源代码建议 MIT，第三方组件遵循各自许可证，不能用应用 MIT 覆盖依赖许可。

## 11. 验收矩阵

| 编号 | 场景 | 必须可观察的结果 |
|---|---|---|
| AT-01 | 无密码 ZIP / 7z | 文件内容逐字节一致，无无效成功密码记录 |
| AT-02 | 加密 ZIP（传统/AES）/7z（含加密文件名） | 错密码可继续有限候选，正确密码完整解压后关联 |
| AT-03 | RAR/RAR5、加密与固实归档 | 每种使用真实样本单独通过，不以“引擎支持”代替软件验收 |
| AT-04 | 各分卷格式、拖入中间卷与缺卷 | 每组一项，缺卷明确失败，缓存完整分卷组 |
| AT-05 | 中文、空格、前后空格密码及重复导入 | 口令原文保留，分组和重复规则符合预览 |
| AT-06 | 分组限定、停用、已记忆但范围外 | 不越过所选范围，不尝试停用口令 |
| AT-07 | 同名输出和处理中发生重名 | 改名或跳过，原有内容完整保留 |
| AT-08 | 坏包、路径穿越、链接、资源超限 | 明确错误，不写出边界，不假报密码错误 |
| AT-09 | 解压中取消、写回中取消、异常退出 | 不发布半成品；有效成品保留；遗留目录可识别 |
| AT-10 | SSD 正常工作与跨卷目标 | 源包哈希不变、最终内容一致、缓存按规则清理 |
| AT-11 | SSD 超配额/磁盘满/移除，目标不足 | 指明阶段；无半成品；按单项失败或共享暂停处理 |
| AT-12 | 清理失败或相似名称非软件目录 | 提示真实遗留位置，不删除无关目录 |
| AT-13 | 本地库与备份、错口令、篡改、损坏库 | 磁盘无原文口令；错误不覆盖当前库；备份可迁移 |
| AT-14 | 默认离线和诊断脱敏 | 常规功能无上传；日志无口令/解压内容 |
| AT-15 | UI 与大队列、高 DPI | 可操作、可取消；真实拖放/选择器/按钮人工或原生验收 |
| AT-16 | HDD→SSD 性能 | 同条件的全流程对比，明确各阶段耗时，允许报告无加速 |
| AT-17 | 双层归档、不同密码、普通文件混合 | 说明文件保留；内包独立目录；两层成功后最终树只写回一次 |
| AT-18 | 内包失败、同名冲突、DOCX 等容器 | 不丢失失败内包/普通文件；不覆盖；不误展开应用容器 |
| AT-19 | 标准与严格模式 | 标准没有额外全量 HDD 回读；严格对目标内容回读并比较；结果准确标注 |
| AT-20 | 解压/复制流中篡改及写回故障 | 流式摘要不符阻止发布；写回失败可保留已验证工作区，重试不必重解 |
| AT-21 | 多层与峰值容量 | 达到层数/累计资源限制时明确停止；释放中间文件不会绕开累计限制 |

静态检查、单元测试、真实归档测试、原生界面操作和性能对比是不同证据；只编译成功不能宣布软件完成。对未测试的格式、分卷变体和平台明确标记“未验证”。

## 12. 推荐技术方向与实施顺序（仅供后续）

推荐候选：.NET / WPF 原生 Windows UI + 独立应用层 + 官方 7-Zip 引擎。口令通过引擎回调或不暴露于命令行的受限通道传递；不能拼接进进程参数或原始日志。SSD 缓存为应用层任务工作目录。

分层、进程、存储、任务树与恢复流程的详细设计见同目录 architecture.md。架构讨论稿推荐“主程序 + 独立解压 Worker”，并建议把独立 Worker 提前到首版；这对原 P1 范围的调整仍作为推荐方案，当前不继续实现。

正式定框架时核实最低 Windows 版本、引擎格式能力和许可证。7-Zip 许可包含 LGPL、BSD 部分及 RAR 解码限制；发布需保留相应说明并满足准确源码/再分发要求。

后续实施顺序建议：规范定稿 → 密码库与直接解压 → 队列及分卷 → 双层展开、SSD 工作缓存与分级验证 → 恢复与全矩阵验收 → 开源文档和发布。停止开发期间只调整本规范与设计稿，不修改应用源码。
