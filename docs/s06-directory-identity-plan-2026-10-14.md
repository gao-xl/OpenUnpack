# S06 目录身份竞态修复执行方案

授权：用户批准先关闭 S06，随后要求“开始”。范围限于当前生产 Core → Worker → Engine 的目录/文件身份保护，保留已有工作区修改，不切换架构。

## 风险与验收目标

原风险 Medium，根因置信度 High：字符串路径检查与复制、发布、删除分离，已批准目录的其他写入主体可改变目录项。保护原始归档、已经校验的输出以及应用拥有的临时目录；不建立对抗同用户恶意进程控制、管理员或内核失陷的隔离边界。

1. Windows 根到叶逐层持有目录句柄，拒绝 reparse 点；所有后续打开/创建/枚举均基于父句柄单个组件。实际测试证明仅共享锁不能阻止属性权限建立 junction，禁止重新解析绝对祖先路径。
2. 移动与删除固定末端对象，通过同一句柄执行禁止覆盖的 rename/disposition；只明确跨卷错误进入复制回退。
3. 递归清理逐层固定对象，保留 ownership 标记直到其他内容成功删除；发生锁冲突、目录替换、身份不符时停止并保留恢复依据。
4. 发布在回读前固定目标树，按原句柄回读；NTFS 实测要求根目录 rename 前释放子项租约，因此先证明目录继承边界及全部子项 ACL 没有其他主体修改权限，再释放子项，根对象句柄全程保留至原子提交。新拥有工作目录在创建时原子赋予受保护用户/SYSTEM/Administrators ACL；旧目录无法证明安全条件则保留待处理。源清理先固定所有分卷，复核原 witness，再删除同一对象。
5. C# 输出创建、复制、回读、分卷输入与来源标记使用操作生命周期租约；不能用祖先检查缓存代替身份固定。
6. 回收站保留原路径恢复语义：先排除既有 DELETE/内容写句柄，再验证单链接源及父目录继承链 owner/DACL，直到可信 protected 边界；保持只读允许 Shell 删除的同对象句柄。多主体可改目录、未知 ACL 或多硬链接无法证明条件时保留源并提示。历史已经授予的安全修改句柄与同用户恶意进程不由此证明隔离。
7. 工作目录租约覆盖独立 Worker 请求之间的空隙；在任何恢复写入前证明旧工作目录的私有权限。工具箱批准凭据绑定卷及文件对象标识，执行时先固定全部待操作源，再复核凭据。
8. 先限制资源，再构造租约链：相对路径最多 128 层，绝对目录链最多 256 层，树租约最多 200,000 个对象。并发缓存任务只在存在活动同缓存任务且请求本身满足上限时按资源等待处理，不突破配额。

## 执行与验证

先跑现有基线，再实现跨层修复。采用真实 Windows 句柄、目录重命名/联接、锁冲突与并发替换测试；覆盖锁释放后正常操作、合法发布、不覆盖、跨卷、只读和清理重试。使用隔离 Rust 构建目录，避免链接缓存相互干扰。

修改后执行 Core 相关单元及真实 Worker 管道、C# 原生引擎回归、严格格式/静态检查、协议与镜像门禁。记录准确执行结果与剩余边界。原生 GUI、干净机器及安装包验收属于后续发布阶段，不能由本轮测试代替。
