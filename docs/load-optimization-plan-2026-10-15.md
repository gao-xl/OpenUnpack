# 1–5 任务负载与工程优化执行方案

授权：用户要求“开始全部任务”，并明确选择“增加到最多 5 个活跃任务并验证”。默认并发保留 1，5 是允许的任务上限；机械盘、未知拓扑和资源安全条件仍可降低实际并发。

## 目标、范围与完成条件

主要目标是控制实际 1–5 任务场景下的资源占用、正确交付、暂停新任务和取消响应。覆盖生产 Core → Worker → Engine；状态刷新、缓存统计、构建/测试组织和小范围架构维护一并评估。保留已有未提交工作及 S06 候选，原生界面仍按此前约定暂缓。

1. 前后端、设置校验与磁盘调度统一支持 1–5，默认 1；实测 SSD 场景达到 5 个同时存在的本轮 Worker，不能用五项队列或配置值替代实际并发证据。
2. HDD/未知磁盘仲裁包含候选缓存端点；暂停命令与任务领取有一致顺序，暂停返回后没有新增领取。允许已经领取的任务完成，不挂起任意原生线程。
3. 缓存展示按请求身份独立记录贡献，过期事件不污染其他任务；实际配额准入仍使用扫描及预留，不以展示估算替代安全上限。
4. 自动引擎线程按配置并发及逻辑核数分配，手动线程值保留；不声称多个独立 Worker 的 50% CPU/4 GiB 限额等于全程序总量上限。先用实际峰值判断是否需要追加资源策略。
5. 串行执行 1/2/3/5 矩阵，固定总任务数与数据量，记录真实 Worker 峰值、批次吞吐、CPU/内存及 I/O、快照耗时。分别覆盖 SSD、HDD、SSD 缓存回写；小样本不能替代长期热稳定或全部格式验收。
6. 负载中暂停只阻止新任务；取消在实际输出进度后触发，记录命令与退出/终态延迟、其他任务完成情况、原始归档摘要及遗留 Worker。取消终态与进程退出目标 5 秒，超时明确失败。
7. 安装构建由 Tauri 负责唯一一次 UI/Host 编译；纯便携分别编译一次。修复 PDB 同名，保留绝对 target、失败即停止、最终便携冻结及真实包内核对。
8. 对齐 Core/Infrastructure 纯路径校验的 128 层限制，并扩充镜像门禁。更正过时的 Core 退役前置条件；本轮不切换生产入口，也不复制整套 NT IO 层。
9. 状态快照先在十项队列及积累历史下测量。按用户场景降低全量增量协议改造优先级，仅对证实的成本做局部优化；完整协议迁移保留单独的设计与验收要求。

## 已知现状与风险

- 当前生产并发硬上限为 4，前后端均需更新；不能只改设置文案。
- 硬件现查为 i5-8500T 六核、约 16 GiB 内存；C 为三星 NVMe，D 为东芝 SATA HDD。原始 JSON 保存在本轮证据目录，测试前记录可用空间/内存。
- 已定位并行缓存进度覆盖（展示错误，不等于配额绕过）、候选缓存盘仲裁遗漏和暂停/领取竞态；须以确定性回归验证。
- 旧物理盘测试会删除传入根下固定名称；应改为本轮独占 UUID/归属边界后才运行。
- 不禁用 S06 身份/ACL 保护、不清空系统缓存、不调整系统电源/内核设置，不触碰个人归档、密码库、任务库或正式安装目录。

## 分步实施与文件边界

1. 保存当前代码摘要、硬件、冻结 Worker 摘要；运行已有调度、进度与恢复基线。
2. 新增独立合成负载夹具和采样脚本，先在旧上限内保存基线（1/2/3/4）；不与编译并行测量。
3. Rust：`coordinator.rs`、`route.rs`、协议常量及设置 UI，修复调度、暂停、自动线程与五并发；补确定性边界测试。
4. Rust：修复缓存展示身份/贡献合并，减少可证实的重复统计；配额安全扫描保持独立。
5. 工程：`prepare-desktop.ps1`、`build-desktop.ps1`、Host lib/main；Infra manifest 和镜像门禁；更新迁移边界文档。
6. 运行后测 1/2/3/5 与暂停/取消；正常返回必须逐文件内容一致、原包不变、缓存可回落、Worker 已退出。样本和基准测量开销记录在报告中。
7. 分层回归：目标 Rust/UI、契约/镜像、严格 fmt/Clippy、完整工作区；构建与负载测量串行，避免再次制造测试超时。
8. 生成新候选并解包检查，运行包内 Worker；保存带日期/轮次的产物、摘要、源包与报告。原生 GUI/干净机器/安装升级及网络/拔盘等未执行项单独注明。
