二、重点缺陷机理深入剖析

1. FT-004：未认证请求连接间歇性中止 (Winsock WSAECONNABORTED 10053)

影响位置：crates/local-api/src/server.rs:486-531 (reject_request)
机理深度定位：在 Local API 处理未通过鉴权的请求体时，state.rejected_bodies 仅配置了 16 个并发许可，且超时等待仅为 250ms。在高并发或请求体较大的测试中，若数据未读尽服务端便直接关闭底层 TCP Socket。根据 Windows Winsock 规范，当套接字接收缓冲区中仍有未读数据时执行 Close，TCP 驱动会直接向客户端发送 RST 报文。客户端在读取 HTTP 401 响应报文头前触发 10053 异常。
整改方案：放宽未认证请求体的丢弃缓冲并保证标准优雅挥手（FIN）。

2. FT-002：代码格式规范差异 (cargo fmt)

影响位置：apps/desktop-host/src/lib.rs
机理分析：新增的休眠/关机命令及上下文菜单注册逻辑换行与 Rustfmt 规范存在微小出入。
整改方案：运行 cargo fmt --all 即可一键恢复合规。

3. ARCH-01：协调器单体职责膨胀 (God Class)

影响位置：crates/core/src/coordinator.rs (8,728 行)
机理分析：单文件融合了调度、SQLite 锁租约、Win32 磁盘 IOCTL 拓扑、文件监控（watcher）、垃圾桶回收（SafeRecycle）等众多逻辑。
整改方案：按规划下沉至 crates/domain 与 crates/application。
