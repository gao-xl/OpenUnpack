# 剩余问题修复范围（2026-10-11）

用户要求先跳过新增设置开关。本轮处理已确认的缺陷，保留 Core 生产任务协调器，不切换整个运行架构。

## 实施决定

- 规则统一限制为 512 个 UTF-8 字节。输出预览只继承归档中明确存在的目录条目，与 Engine 的提取策略一致；输入预览保持现有扫描规则。

复核后补充：输出预览通过无文件操作的 Worker 规则试算入口复用同一 Engine 输出规划器，避免 Rust 与 .NET 的 UTF-16、大小写规则差异。入口限制为 1 MiB JSON 输入、1000 条路径、100 条规则与有界退出等待；旧 Rust 输出模拟器已移除。数据库增加 Core 共享、新 Store 独占的进程寿命文件租约；不支持租约的历史程序仍要求完全退出后才能迁移。
- 归档检查使用用户已配置的条目数和展开字节预算。长清单通过已验证的原子 spill 文件传输；inline 和 spill 使用相同的元数据安全检查，退出未确认时保留工作区。
- 新分层的取消等待使用每会话共享退出结果，不在等待期间占用全局会话表锁。快照返回真实错误和统计。首次写入新数据库格式前备份旧格式，并在同一写事务提升版本，禁止旧 Core 误读新数据。
- 桌面构建钩子显式指定 UI 工作目录；便携构建即使跳过依赖准备也重新编译 UI。复制程序和安装包时使用 Cargo 实际的 target_directory，支持独立构建缓存。
- NSIS 当前用户默认程序目录调整为 `%LOCALAPPDATA%\Programs\OpenUnpack`；现有数据目录 `%LOCALAPPDATA%\OpenUnpack` 保持原位。使用固定 Tauri CLI 2.12.1 上游模板，仅修改默认目录、旧目录恢复与数据目录安装阻断。自定义安装目录仍受尊重；旧默认安装目录不再被自动恢复。

## 改动边界与恢复

安装目录调整不搬移、读取或覆盖个人密码库和任务库。新模板保留上游按发行清单删除程序文件的卸载行为。目录冲突在复制程序前失败；不会尝试删除冲突目录。新分层数据库备份只导出到新路径，不原地覆盖。

源代码不提交、不清理已有工作区改动。新层的修复不构成生产迁移完成；速度事件接入、完整任务循环迁移及后续功能另列。

## 验证

先运行现有基线，再检查中文规则边界、显式与隐式目录、原生 7-Zip 大清单与预算拒绝、并发取消和数据库失败/恢复。用正常 Tauri 构建钩子生成桌面程序与 NSIS。安装测试使用独立产品名、注册表键及合成数据，验证默认目录、旧目录跳过、升级、卸载和数据摘要保持。

独立干净 Windows、缺少 WebView2 的离线安装、第二账户恢复及真实硬件故障仍需各自证据，不能由本机单元测试替代。
