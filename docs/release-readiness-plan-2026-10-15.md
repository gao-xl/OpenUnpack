# 发布前剩余任务实施方案

日期：2026-10-15。授权：用户在收到资源控制、缓存策略、历史记录、维护、桌面验收和发布可靠性清单后要求“开始全部任务”。保留工作区全部已有改动、用户数据及前轮冻结候选；本轮不发布、不提交、不进行个人磁盘满盘/拔盘或系统断网操作。

## 目标和边界

1. 所有 Worker（批量解压、归档浏览、规则预览）共享内存准入预算；保留最多 5 个活跃任务、默认 1。池总额为物理内存一半且不超过 8 GiB；每次运行按当前并发分配不超过 4 GiB 的份额，并落到 Windows JobMemoryLimit。低物理/提交可用余量时 FIFO 等待，支持取消；额度在确认进程退出后释放，不能因 future 中止而提前复用。保留现有 Job Object UI 安全限制。Host/WebView 不受该池硬限，保留系统余量；现有线程分配和单 Worker CPU 限制不冒称全应用 CPU 硬总量。
2. 缓存开关保留关闭即直写；附加 cachePolicy=auto/always，旧设置缺字段按 auto 读取。自动路由不再把 expandNested 当作已发现嵌套，也不把压缩包大小估算出的条目数当作真实条目。证据不足优先直写；always 用于明确要求 SSD 中转的场景，但空间、配额、路径与物理盘仲裁仍生效。不承诺缓存必然更快。
3. 旧 snapshot/history 命令保留；新增 queue_snapshot，仅克隆全部非终态、待核对或保留工作区的记录，以及最近 20 条其他终态记录，保留活跃节点与完整 recoverableCount。生产初读和订阅均使用有限快照。新增 history_page 的有限摘要和 job_details 按需详情；页长 1–100、稳定排序、筛选、全量计数、过期响应门控、删除后夹紧页码、失败保留可读结果。UI 明确队列显示范围，历史不丢失，不改数据库 schema。暂不实施旧的全量克隆后求差异方案。
4. 修复真实 ToolboxPage Effect lint 警告，保留预览失效和异步竞态保护；更正前轮误记为 ArchiveBrowser 的位置。Host DTO 入口已直接使用 protocol，不为完成清单重复机械修改；Core 生产迁移需继续遵守安全 IO 对等门槛，本轮不切换完整运行时。
5. 补充可重复的真实 Worker 故障与恢复回归，以及安装完整载荷、发行签名门禁。使用当前候选真实窗口和独立 OPENUNPACK_DATA_DIR 做桌面验收。安装仅用独立 OpenUnpackAudit-UUID 产品，核对解包自同一安装包的完整载荷；不能把同机重复安装当跨版本或干净机器验收。
6. 本机无 CodeSigning 证书，未发现可直接使用的干净 VM/Sandbox，现用磁盘均为个人使用中的 NTFS 固定磁盘。用户已明确回复“目前没有，先完成本机可执行部分”，因此本轮验收范围限本机可执行项。签名、干净机器、缺 WebView2、真实满盘/拔盘/网络中断保留为正式发布的外部条件，并交付步骤和证据结构，不伪造通过。

## 文件与协作边界

- Rust 资源：Core worker.rs、Infrastructure 完整镜像、Coordinator 的 Worker 调用和配置接入、相应回归；不编辑快照或路由方法。
- UI/协议：protocol desktop DTO、Host 命令/权限、TS API/类型、HistoryPage/QueuePage/SettingsPage/ToolboxPage，以及 Coordinator 的快照/历史方法和测试。
- 主线程缓存：route.rs、Coordinator decide_route/validate_settings/extraction_compatible、缓存场景夹具；负责最终格式、契约、完整工作区和构建，不与其他 Rust 构建争用 target。
- QA：独立可靠性集成测试、安装验证脚本和签名门禁；不触碰真实安装和个人数据。
- 报告：本方案、本轮报告、README/验收清单当前证据链接；原始日志在 `_workspace/release-readiness-2026-10-15/`。

## 执行顺序和验收

1. 冻结修改前源码/脏状态，运行既有目标基线。当前 route 10/10、前端 133/133；lint 0 错误、1 ToolboxPage 警告。
2. 分别实施共享资源、分页与有限快照、缓存策略、故障/发行门禁。为确证缺陷建立有区分力的回归；低影响的机械维护不堆叠镜像测试。
3. 串行运行资源/缓存/分页目标回归，再执行前端、协议契约及负向自检、镜像门禁、fmt、严格 Clippy、Rust 全工作区。C# 未改时复用冻结运行载荷，仍运行包内原生协议核验。
4. 冻结最终源码后在不并行编译的条件下复测五 Worker 重叠、低资源等待/取消、输出内容和源包摘要、进程退出。计量只覆盖实际测到的范围。
5. 构建本轮新候选、核对 Host 与全部 Worker/runtime/许可文件、源包和校验和。再做隔离数据的真实窗口验收及可执行的同机隔离安装测试。
6. 汇总已实现、已验证、环境限制和后续步骤；所有失败先定位修正，未执行/默认忽略不能记通过。独立测试中的模拟故障不冒充真实物理介质验收。
