# 本地 MCP 批量解压连接器

用户已授权开始开发；范围承接“一句话批量解压”的本机连接器及按任务集合启动、查询、取消和保留选项重试。

## 当前基线

- 在现有 `codex/open-unpack` 分支做局部补丁，保留原有未提交与未跟踪文件。仓库没有本地 main/develop 或 remote，无法核实远端同步状态；不新建发布、提交或推送。
- 生产链继续使用 React/Tauri → Core Coordinator → Worker → Engine；HTTP API 与桌面共用状态。
- 已有 `start_jobs` 操作共享待处理队列。API 重试原先重新读取全局设置，新增任务可能被正在运行的桌面调度器领取。
- 变更前的相关文件快照与 Git 状态：`_workspace/mcp-20261020/before/`、`results/source-before.json`、`results/git-status-before.txt`。

## 实施

1. Core/API 增加 `start_selected_jobs {jobIds}`，全量验证 ID、状态与授权后再修改调度范围。保留旧 `start_jobs`。API 运行可增加选定任务，正在运行的 GUI 调度或暂停队列需由用户先处理，禁止偷偷启动其余任务。
2. 重试可选择 `preserveOptions: true`，保持任务原输出、密码组等选项；默认 false 兼容既有调用。等待资源的取消与重排同样遵守选定范围，核查调度结束与新增任务间的竞态。
3. 新建独立 `apps/mcp-connector`，用官方 TypeScript SDK 提供 stdio 工具：计划、提交、状态、限定启动、取消、重试。仅访问既有本机 API，密码组留在本机使用，不提供明文、备份、删除或任意 RPC 工具。
4. 计划在连接器进程内限时保存，单次提交去重；已提交任务用 jobIds 跨连接复查。API 添加结果不明时不得自动重试添加；启动失败应返回已接受 ID，允许之后仅重试启动。
5. 文档包含本机授权、安装/运行、配置、状态与恢复边界；源码发布需包含连接器源码、锁文件和说明。

## 验收

- Rust：选定集合以外任务不执行/不变状态，空/重复/不存在/非待运行 ID 整体拒绝，未授权批次不部分修改；GUI/API 竞争、资源等待与冻结选项重试回归。
- MCP：使用真实 SDK 客户端完成 initialize、tools/list、tools/call；HTTP 合约测试覆盖鉴权、拒绝重定向、超时、计划过期、重复提交与启动失败后的恢复。
- 原生集成：隔离的数据目录、人工 ZIP 样本、新 Host 与现有 Worker/7-Zip，通过真实 HTTP 与 MCP 提交并核对结果内容；另置无关队列任务确认其不被选定启动执行。
- 运行相关构建、格式/Clippy、协议同步与依赖检查。测试不使用个人密码库，也不等同于安装、签名、真实磁盘或外部 AI 客户端的发布验收。

## 本轮范围

连接器提供工具，用户的 MCP 客户端负责自然语言理解。首版不增加内置聊天模型、公开网络服务或第二套解压引擎；不改变 Worker JSON 协议。
