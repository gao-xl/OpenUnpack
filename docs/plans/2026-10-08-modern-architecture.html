契约规则
界面 → 核心版本化命令与错误码；分页列表、阶段事件、快照重连。前端不读写数据库、不传文件内容、不任意启动程序。
命令权限显式配置应用自定义命令权限；核心检查授权来源/目标、窗口和任务归属。不能只靠插件 capabilities。
核心 → Worker检查协议、子进程身份、requestId、attemptId 和运行代次；消息有界，迟到结果无效。
口令通道只传当前候选，通过原生回调使用；不进参数、环境变量、日志、任务数据库或清单。
取消与退出先协作取消，超时终止 Worker/子进程，确认句柄关闭后清理；主进程退出约束子进程退出。

SSD 处理与验证范围

来源 / 分卷确认→存储预留→按需缓存源包→外层 → 内层展开→封存最终清单→顺序写回→所选验证 / 发布
  • 最终清单直接引用节点文件，正常路径不额外复制一份 SSD 合并结果；中间层留在工作区。
  • 同一物理 HDD 默认一个活跃 I/O 阶段；涉及多盘时一次取得整组许可。盘符不同不等于物理盘不同。
  • 实时占用、未消耗预留和保留空间分别计算；失败尝试/等待工作区也占配额，预留转实占不重复计数。
  • 每个内包独立候选与结果；部分交付需显式选择，保留未展开内包及原因，不计全部成功。
模式实际验证界面如何说明
标准提取时摘要 + 引擎结果；写回时从源流计算摘要并比较，检查读写错误与数量/大小。标准验证完成；未完整回读目标。源流摘要不证明目标物理存储。
完整目标回读写回后刷新并读取目标，按期望摘要比对；记录真实读取方式。完整回读结果与范围。未实测时不声称绕过系统缓存或保证断电持久性。

完整来源指纹、采样指纹和元数据指纹分开；强密码关联只用完整内容指纹。哈希、解码、创建小文件和 HDD 最后写入仍需时间。

错误处理、防死锁与无进展处置

先区分普通错误、资源等待、无进展和循环死锁。心跳与超时用于发现和处置异常，不是无死锁证明；没有等待循环证据时，界面显示“未响应”或“暂无新进度”。

情况处理与恢复
密码耗尽 / 缺卷 / 坏包 / 校验失败影响当前节点，等待补密码/卷/新源后再试；含歧义的引擎错误不强判成密码错误。
空间不足 / 设备不可用暂停依赖该资源的任务，确认停止后释放临时许可；保留文件继续占配额，给出换位置/清理/调配额入口。
短暂占用 / 数据库繁忙有限次数与总期限的退避；旧快照需释放并重新校验。不可写/损坏不当作普通繁忙，更不创建空库覆盖。
作业崩溃 / 未响应独立探测、协作取消、必要时终止进程树；确认真实退出后新进程/新操作重试，未确认不清理或复用目录。
发布提交结果不明进入发布待核对，依据意图与归属恢复；不盲目重复发布或删除可能已交付的结果。
清理 / 密码记录保存失败保留文件完成状态，显示独立提醒，幂等处理后续动作，不重新解压成品。
典型死锁：只有一个 Worker 槽位，父任务占着它等待内包，内包又等这个槽位。规定外层封存后先释放执行许可，再调度内包；结果文件引用不等于执行许可。
  • 状态锁只做短内存操作，不跨 await、不持锁等待 I/O 或其他组件；数据库事务不等待用户、Worker、保险库或发布。
  • 阶段所需物理盘、执行槽位、CPU/内存由统一准入一次授予整组，拿不全就排队，不持部分许可等待。
  • 额度增长被拒后停到可确认边界，进入空间不足；不能占着执行名额等待只能由自身完成后释放的空间。
  • 取消/探测使用独立控制接收路径，数据接收器持续排空；普通进度可合并，终止/错误/结果不静默丢弃。
  • 长时解压、复制与回读隔离到作业进程。异步超时或 abort 不能可靠强停已开始的阻塞线程。
  • 监视阶段、最后控制/引擎/读写回应、等待对象和许可持有者；真实退出与句柄关闭前不回收资源。睡眠恢复后重新探测。
等待超期 / 失联→探测与诊断→协作停止→必要时终止 / 确认退出→核对提交点→重试 / 保留成品 / 待处理

界面区分等待资源、无新进度、作业未响应、正在停止、停止待确认、发布待核对与完成后处理待办，提供实际可用动作。系统设备卡死时不能承诺固定秒数停止；无退出确认就保留归属和工作区。

新增验收：单 Worker 嵌套、反向盘资源申请、额度拒绝、持续数据库繁忙、进度洪泛/接收器停读、原生或传输作业失联，以及这些状态下取消；发布改名后退出仍须保留成品。记录等待图与资源最终释放，不以“没超时”证明无死锁。

技术依据：Tokio 状态与锁、阻塞作业限制、SQLite 隔离、Windows 进程树。本节是设计约束，尚未实现或演练。

唯一状态权威与恢复提交点

存储所有者与内容
SQLite核心单写入者；任务/节点/尝试、工作区、发布意图、成功 outbox、格式版本；不存口令。
账户保护密码库当前用户 DPAPI 全库保护，原子替换；加密/读取失败禁止明文降级或空库覆盖。迁移备份另设口令。
不可变清单文件版本、路径映射、大小、摘要与能力证据；不与数据库争夺可变阶段。
配置无口令的全局默认值；根任务开始时冻结配置快照。

发布意图先落库 → 目标卷临时目录复制验证 → 归属和准备状态 → 同卷非覆盖改名 → 数据库提交发布与成功事件 → 独立清理。名称冲突变更先更新意图。

改名成功后保留成品。改名后数据库未提交，核对意图、归属和必要内容证据后补记；无法确认则等待处理。成功 outbox 携带密码 ID 与口令版本，只有仍存在且版本匹配的记录才按 eventId 幂等更新；改口令或删除后跳过关联并确认事件，不重复计数，不把旧成果关联到新口令。

多个存储没有共同原子事务。清理前核对工作区归属、引用与活跃句柄，不能仅凭目录存在推断成功。

验收矩阵与完成标准

验收面必须观察的结果
路线 PoC建议一万任务样本，列表虚拟化/高频更新；中文输入、真实文件夹拖放、键盘/DPI；干净机器完全离线安装。
原生引擎真实加密 ZIP/7z/RAR、固实与各分卷；密码回调、增量摘要、取消、Worker 崩溃后界面可操作。
嵌套与部分完成普通文件保留，内外不同密码、缺密码/坏内包、仅重试失败节点、最终映射和根结果准确。
发布与恢复每个发布窗口强制退出；未发布不算成品，已发布保留，不覆盖无关目录、不重复成功计数。
资源与验证缓存/目标满、拔盘、未知展开大小、同物理盘多卷；标准无额外完整目标回读，严格回读确实验证目标。
数据与性能错口令/账户保护失败不覆盖现库；参数/日志/数据库/清单无口令；相同源和目标比较全部耗时与峰值占用。

当前完成标准是设计边界、契约、状态、数据、UI 分类和验收规则可供评审；尚无构建、真实解压、性能或原生桌面验收。性能阈值与依赖版本由后续 PoC 锁定。
