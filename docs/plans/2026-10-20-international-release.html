OPENUNPACK · RELEASE PLANNING · 2026-10-20

让国际用户能够找到、安装、理解并持续使用 OpenUnpack

目标：先交付一个可验证的 Windows x64 英日测试版本，再逐步扩大分发。三语界面已经有基础，接下来优先补齐发行质量、首次使用、安装信任、帮助和反馈。当前状态：准备阶段，尚未达到正式国际发行条件。

范围待决策当前缺口目标体验推进顺序验收发布与回滚证据

范围、假设和权限

本方案覆盖 Windows 桌面产品的国际发布准备，初期界面语言为简体中文、英文、日文。以免费限量测试作为规划默认，商业模式尚待维护者决定。先服务需要批量解压、嵌套归档、个人密码管理及可恢复任务的用户。

本轮只创建规划文档，不改产品代码、不购买证书、不注册服务、不公开仓库、不上传包、不联系用户。暂不扩展 macOS/Linux/ARM64、新语种、云密码服务或支付系统。Windows 版本的支持声明必须绑定实测环境，并明确旧系统的支持边界。

数据、接口与隐私影响

  • 语言偏好沿用现有 localStorage，新增“无已存偏好时系统匹配”的决策函数，不迁移业务数据库。缺失译文在开发检查中暴露，未知语言明确回退英文。
  • 错误本地化先覆盖常见可操作分类：密码错误、缺卷、损坏/不支持、磁盘不足、权限、目标冲突。生产链路补稳定 code + 安全参数，保留已有调用兼容；逐个 DTO/IPC/HTTP 契约测试，不全量重写诊断协议。
  • 诊断包仅用户主动导出，默认去除密码、备份口令、API key、归档内容及个人路径；内容可预览。不要求用户发整个密码库或数据库。
  • 隐私页面必须说明密码保护的 Windows 账户绑定、历史元数据/路径并非全盘加密、备份与数据删除；逐项核对联网行为，网站统计/下载日志与桌面遥测分开说明。若进入特定市场或收费，针对主体、地区、收集数据和消费者业务单独核对适用义务；本方案不作法律合规完成结论。
  • 用户产品许可与第三方许可分别维护；检查最终包中的 7-Zip、.NET、Tauri 等材料和来源。7-Zip 有混合许可与 unRAR 限制，不能把整个分发包笼统标为仅 MIT。既有 THIRD_PARTY_NOTICES.md 和法律材料收集脚本应继续作为来源。
  • 自动更新若实施，Windows Authenticode 和 Tauri 更新签名分别管理。更新前等待/安全停止任务，验证签名，失败不损坏现有安装；已有不兼容数据库迁移时，保留同版本备份并限制降级。

主要风险与处理

  • 源代码和多个冻结候选混用：分别绑定源码、载荷、哈希与结果；旧运行时修复不能仅靠修改版本策略。
  • 翻译准确但不能上手：让母语用户走完整任务，优先校对删除、覆盖、备份、失败和恢复文案。
  • 签名预算和资格不确定：先决定发行者身份，再核对可用签名服务；微软文档明确签名仍可能经历 SmartScreen 信誉积累期。
  • 国际推广承诺过大：以已验证的格式、系统、功能和恢复语义为准，不宣传“绝对安全”“所有格式”或“SSD必然更快”。
  • 收集反馈时泄漏内容：使用主动导出与预览、最少字段、私密安全渠道，禁止要求真实密码与私有归档。
