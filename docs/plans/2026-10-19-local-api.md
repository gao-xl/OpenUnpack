# OpenUnpack 本机全功能 API 实施方案

日期：2026-10-19。用户已确定：同一电脑的第三方软件/脚本调用，覆盖全部现有功能，采用成熟 API 框架。

## 决定

使用 Axum 作为 HTTP 框架，Utoipa 提供 OpenAPI，Swagger UI 提供本地交互文档。直接接入现有 Tauri 宿主及其 Coordinator，所有客户端与界面共用同一任务队列、数据库、密码库、资源限制和 Worker；不另开第二个 Coordinator。

这是针对当前 Rust/Tauri 项目的选择。FastAPI 的自动校验和文档适合 Python 服务；在本项目引入它还需要分发 Python 并维护到 Rust 宿主的跨进程桥接，增加部署和故障恢复路径。第三方调用方不受服务端语言限制，PowerShell、Python、C#、Node 和其他支持 HTTP 的应用都能使用。

官方依据：[Axum](https://docs.rs/axum/latest/axum/)、[Utoipa](https://docs.rs/utoipa/latest/utoipa/)、[Swagger UI 集成](https://docs.rs/utoipa-swagger-ui/latest/utoipa_swagger_ui/)、[FastAPI 功能](https://fastapi.tiangolo.com/features/)。本文不宣称某框架在所有场景性能更好。

## 对外接口

- 仅绑定 `127.0.0.1`；首次默认关闭，设置页启用。默认端口 47980，可更改；端口占用给出状态错误。
- 使用 `/api/v1`，请求和返回为 JSON；主入口 `POST /api/v1/commands` 使用带 command/args 的完整类型定义，兼容别名 `POST /api/v1/commands/<命令名>`。沿用现有桌面命令的 camelCase 参数，避免维护两套业务规则。
- `GET /api/v1/health`、`GET /api/v1/capabilities`、`GET /api/v1/events` 提供健康、能力目录和 SSE 状态失效事件；客户端据 revision 拉取其获准读取的最新数据。
- `/docs` 和 `/openapi.json` 提供本地文档；Swagger 静态资源随程序打包，不依赖用户机器上的 CDN。
- 安全审计发现 utoipa-swagger-ui 10.0.1 的 ZIP 构建依赖含已知公告，故不使用该集成包。直接嵌入官方 Swagger UI 5.32.6 静态文件；保存原始 LICENSE/NOTICE、来源 ZIP 与逐文件哈希，法律材料收集核对实际资产，不引入 ZIP 构建解压库。
- 统一错误包含 `requestId`、稳定错误码和说明；区分未认证、无权限、参数错误、资源冲突、请求过大和内部异常。不返回堆栈、请求体或密钥。

## 全功能覆盖表

| 功能 | 对应现有业务入口 |
| --- | --- |
| 状态和历史 | snapshot、queue_snapshot、history、history_page、job_details |
| 扫描和排除预览 | scan_sources、cancel_scan、preview_exclusions、cancel_preview_exclusions |
| 队列控制 | add_jobs、start_jobs、pause_jobs、cancel_jobs、retry_job、retry_node、remove_job、clear_completed |
| 恢复和清理 | recover_job、clear_history；继续使用已有状态机、源保护和缓存归属检查 |
| 密码库 | passwords、save_password、delete_password、reveal_password、copy_password、bulk_password_action |
| 密码导入 | read_import_file、preview_import、confirm_import；保留预览令牌与失败原子性 |
| 加密备份 | export_backup、preview_restore_backup、confirm_restore_backup；保留备份路径保护和口令校验 |
| 设置 | 读取及 save_settings，界面相关设置仍同步到实际主窗口 |
| 归档检查 | inspect_archive、cancel_inspect_archive |
| 文件工具 | preview_toolbox_operation、execute_toolbox_operation；保留预览令牌和批准路径规则 |
| 桌面辅助 | open_path、pick_files、pick_directory、pick_save_backup、pick_open_backup；须单独授予桌面交互权限，文件选择会在本机弹窗 |

API 不为第三方提供管理 API 密钥或扩大自身授权的入口。管理权限保留在受信任的本机设置页；这不减少上表的既有业务覆盖。

## 认证和文件授权

每个应用使用独立随机密钥，通过 `Authorization: Bearer ...` 传递；密钥只在创建时显示，持久化仅保存摘要、名称和权限。支持查看应用、撤销和重新创建密钥，撤销后不再接受新请求。

权限按业务分组：任务读取/管理、文件读取/修改/删除、密码元数据读取/管理、密码明文读取、设置读取/修改、桌面交互。导出可由调用方解密的密码备份也要求密码明文权限；复制密码到剪贴板同样如此。低权限状态接口不返回未授权的密码元数据或设置。

第三方只能使用设置页授权的读取/写入目录。每次调用都验证规范化路径，并保留原有 Core/Worker 的路径与非覆盖写入保护；不能用 API 请求自行授予目录权限。创建 API 应用时通过本机目录选择器批准目录。添加任务时需检查实际源卷、输出及缓存路径；改变源清理策略或执行文件删除需对应权限。

浏览器来源默认拒绝，仅允许 API 自己的文档来源；不启用通配 CORS，不从 URL 参数或 cookie 接受密钥。验证 Host，防止任意域名通过本机重绑定访问。限制请求体、并发和长期事件连接，不记录密钥、密码、备份口令或导入正文。

## 工程改动

1. 新增 `crates/local-api/`：框架服务、密钥/授权模型、持久化、操作目录、OpenAPI、统一错误和传输测试。通过后端接口接入业务，便于独立测试 HTTP 安全边界。
2. 新增 `apps/desktop-host/src/local_api.rs`：宿主生命周期、授权后的现有命令调度、目录批准、状态事件桥接，以及本机管理命令。
3. 更新 Host 注册、权限清单及必要生成配置；新增命令仍验证真实主窗口身份。API 自身不会伪装成外部 WebView 或取消原有 IPC 验证。
4. 新增设置页“第三方应用/API”面板，提供启停、端口、运行状态、应用名称/权限/目录、创建/撤销密钥、文档地址。
5. 更新 workspace、锁文件及必要的协议 schema 支持；不改变现有 Worker 协议与备份格式。
6. 新增 API 使用文档、PowerShell/Python 调用示例和完整能力清单。同步发布法律材料与新增依赖审计。

## 实施和验收

先完成当前四类修复的冻结验证及候选，保留独立证据，再接入新 API。API 分为传输/授权、宿主调度、设置页和实际全链四步，每步通过后继续。

验收必须包含：

- 默认关闭、仅 loopback、缺失/错误/撤销密钥拒绝、权限不足拒绝、Host/Origin 拒绝、正文/并发限制及错误脱敏。
- 每个现有桌面业务命令均在 API 能力目录和调度器中有对应项；文档与实际路由一致。
- 目录外、伪造分卷、未授权输出/缓存、敏感明文和删除权限的负例；预览令牌仍绑定实际内容。
- 第三方通过真实 HTTP 提交有效压缩包、启动、读进度、校验实际输出；取消/重试/历史以及密码 CRUD、导入、备份、设置和工具的代表性正反例。
- 同时保留原 UI、Rust、C#、IPC/镜像门禁；构建新的本机可执行候选并绑定实际 Worker/runtime/7z 哈希。
- HTTP 框架/mock 测试不代替真实 Host/Worker；桌面弹窗、剪贴板和原先受阻的原生交互另列实际证据，不能由 HTTP 测试推断通过。

## 兼容和回退

API 配置及应用授权独立存放，不迁移现有密码库或任务格式。关闭 API 即停止监听，现有桌面任务仍由原 Coordinator 管理；删除/撤销应用不会删除业务数据。保留修复候选和原版本，新增 API 不影响旧桌面调用协议。此次不部署公网/局域网服务，也不安装 Windows 服务。
