01 · 目标、范围与授权

目标：把 OpenUnpack 的真实可运行源码、可验证的 Windows x64 发行物和维护规则一起交付给社区，让新贡献者可以从干净克隆构建，用户能判断下载文件的来源、能力和限制。源码公开、Beta、Stable 分别验收。

  • 范围：现有 Windows 桌面、Worker/Engine、Local API、CLI、本地 MCP 连接器、测试、必要示例、许可证、构建脚本和仓库治理。保持 React/Tauri → desktop-host → Core Coordinator → Infrastructure WorkerClient → .NET Worker → Engine 的单一生产链。
  • 首发不承诺：macOS/Linux 桌面、Windows ARM64、创建压缩包、暴力破解、物理 HDD/SSD 性能提升比例、未测试环境的兼容性。API/CLI 的跨平台实验单列状态。
  • 保留当前 MIT 自有代码许可；第三方材料保留原许可。当前私有工作区和 Git 历史不做重写、清理或公开。
  • 本轮已授权：修复、构建、测试、只读审计和本地方案。建远端仓库、推送、公开、发 GitHub Release、群发宣传均留待结果可审阅后由用户决定。

这是发布与开源执行方案，不涉及新产品界面设计；页面中的状态来自证据，不会运行任何发布命令。

04 · 三条发布线与硬门禁

门禁通过条件阻断行为
G0 · 源码可公开公共导出不含第三方分析/反编译、个人记录、秘密、用户归档/密码库；生产文件完整；许可证和测试夹具来源清楚。未通过：禁止公开仓库、源码 ZIP 和包含源码的 CI 公共日志。
G1 · 可重建干净导出/克隆，锁定依赖完成全套构建和检查；没有原工作区缓存、私有 _workspace 或未跟踪文件依赖。失败：修导出/依赖/构建脚本；禁止靠复制本机缓存宣布可构建。
G2 · 功能与数据完整 Rust、C#、UI、MCP、契约和真实 Worker 管线通过；原生回收、取消/重试、损坏归档与授权拒绝符合预期。数据损坏、误删、越权、密码泄露、未验证发布立即阻断全部二进制发行。
G3 · 成品同一性Setup、portable 解包文件逐项核对；实际 runtimeconfig/CoreCLR/hostfxr 为策略版本；完整候选 GUI 有独立证据。载荷过期/漏文件/哈希漂移：重建、冻结并重测受影响链路。
G4 · 安装与兼容Win10/Win11 干净机安装、启动、升级、卸载；普通用户、中文空格路径、WebView2 有/无；数据保留与恢复确认。本机解包和 helper 测试不能替代实际产品安装；缺环境标 blocked。
G5 · 信任与供应链可信发行者 Authenticode，预期证书匹配/有效时间戳；签名后重新打包校验；SBOM/许可证/对应源码/来源证明齐全。未签名不满足公开发行门禁；本方案的 Beta 与 Stable 均要求可信签名，保留实际失败/缺失状态。
G6 · 对外发布用户审阅最终清单、已知限制、仓库归属及公开范围；先 Draft 挂齐资产，核对下载哈希，再明确发布。没有批准不建公开仓库、不推送、不发布。任何仍未执行项不能填 passed。

源码公开：G0+G1 与可公开文档完成即可单独评估，不代表软件已验收。Beta：G0–G4 的核心功能与必需安装项均完成，G5 签名与供应链材料完成，G6 完成。Stable：G0–G6 全部完成，当前条件忽略的发布范围用例补齐或从支持承诺中明确排除并有替代安全证据。

测试状态固定为 passed / failed / blocked / not_run / ignored。总览可显示已关闭问题，但绝不把 ignored、未执行 GUI、签名政策单元测试算作成品通过。

05 · 公共源码：干净导出而后建仓

推荐路径：保留原私有仓库，在独立目录生成经过审阅的导出；从空 Git 历史开始。相比重写现有历史，工作量更可控，且可避免遗漏旧提交、分支、标签中的敏感或第三方材料。只有全历史权属/秘密审查通过后，才考虑保留历史。

公开清单内容/规则
生产源码apps/desktop-host、apps/desktop-ui、apps/mcp-connector；crates 中现行 domain/infrastructure/core/protocol/local-api/CLI；src/OpenUnpack.Worker 与 Engine。以 Cargo workspace /项目引用/运行时资源图为准，不能只按 git ls-files 导出。
构建输入Cargo.toml/lock、global.json、Directory.Build.props、sln、npm package/lock、工具链与运行时策略、全部需要的构建脚本、Tauri installer/ACL/assets/Swagger provenance。
测试与示例本项目合成夹具和有确切来源/许可的上游测试归档；tests 全部必需资源；examples 中 API/MCP/CLI 实际文档引用的内容；scripts/integrations 的 .sh/.bat。
文档与治理README/英文说明、CONTRIBUTING、SECURITY、CODE_OF_CONDUCT、CHANGELOG、LICENSE、THIRD_PARTY_NOTICES；精简后的用户/开发文档、CI、Issue forms、PR 模板。私有验收原始日志只保存于私有证据库。
明确排除整个 .workbuddy、.pi、_workspace、gemini-subagent、.git、agent 对话/记忆、第三方反编译/分析、私人路线图/绝对路径、.env、私钥/PFX、token、vault/SQLite/备份、用户归档、构建缓存、node_modules、下载工具二进制。
按用途审阅Docker/跨平台脚本可作为实验源码公开，但不混入 Windows 已支持承诺；没有使用或含私有路径的文档不自动公开。

现有 scripts/package-source.ps1 有明确树与扩展允许清单，并调用 audit-source.mjs；这比直接打包仓库安全，但尚遗漏 CODE_OF_CONDUCT、部分 integration 脚本/示例和容器文件，需要先补齐适用范围。docs 当前递归允许 .md/.html，必须新增“可公开文档清单”，防止私有报告随源码 ZIP 外泄。

  1. 生成 file-manifest：相对路径、SHA-256、用途、来源/权属、是否必需。跨 Cargo/.csproj/npm/文档引用核对；对未跟踪生产文件逐项纳入。
  2. 补导出白名单与敏感拒绝规则；禁止链接、目录穿越、大小写冲突。新增 .gitignore 防误加入 .workbuddy/.pi/_workspace/.env/私钥；原已跟踪历史不作修改。
  3. 对导出做秘密扫描（全量打码报告）与人工隐私/版权审阅。扫描通过不等于权属成立；有来源疑问的代码必须查明、替换或移除，并补功能验证。
  4. 从导出独立目录重建并执行 G1/G2。隐藏原 tools、artifacts、node_modules、target 与私有资料的访问依赖；所有下载验证固定来源/版本/摘要。
  5. 审查完成后再在新目录建立 Git 仓库、逐清单提交；禁止在原脏工作区 git add . 或重写历史。首个公共提交记录导出清单摘要和真实贡献归属。

后续检查命令示例（需固定并校验 Gitleaks 发行版本，报告仅私有保存）：

# 只有选择保留原历史时，必须覆盖所有引用；输出保持打码。

08 · CI/CD 与仓库权限

现有 .github/workflows/windows.yml 已采用只读 contents 权限、固定 Action SHA、锁定 Node/Rust/.NET，并上传本地候选；目前单一 windows-latest、60 分钟 job，尚没有正式签名、干净机验收、受控发布或 SBOM/来源证明。拆分任务后按实际测量设置超时，不能删检查换绿灯。

工作流/触发职责权限与通过标准
verify-pr.yml / PR 与 mainformat、architecture、契约、严格 Clippy、UI 类型/构建/lint/test/a11y、MCP、C# 及安全策略；独立依赖漏洞审计。contents:read；fork PR 无签名密钥；脚本/Action 全 SHA 固定；失败阻断合并。
native-integration.yml / PR、手动Windows 真 Worker/Core 全套、DPAPI、命名管道、回收站、真实 HTTP；固定干净 target/私有 TEMP。无发布权限；合成用户数据；明确交互桌面前提，宿主无交互时 GUI 为 blocked 而不是 passed。
candidate.yml / 受保护版本引用手动触发冻结源码及锁文件→收物料→构建一次最终 Host/Worker→Setup/portable/source→解包核对→QA。artifact 绑定 sourceManifestSha、commit、runId、平台和 payloadSHA；下游不能下载“latest”代替该产物。
sign-release.yml / 已通过候选审核环境访问签名服务→签内部自有 EXE/DLL→重新生成安装包并签 Setup→重算每层摘要→供应链证明。仅该 job 的签名身份/OIDC，审核者限定；不在仓库存 PFX；PR 不可调用。签后完成最终载荷身份验证，并对最终成品完成 GUI、干净机安装及必要功能回归，不能仅做 smoke。
publish-release.yml / 用户批准后核对同一签名候选的所有证据→创建 Draft→上传全套资产→下载复核→Pre-release/Stable 人工放行。只该 job contents:write；证明 job 单独 id-token:write + attestations:write；protected tags / environment。
dependency-maintenance.yml / 定期锁文件更新 PR、组件来源/许可证变化检查、安全公告复核，不自动合并运行时或引擎更新。只读扫描或最小 PR 权限；用户执行建仓后再配置 schedule。

主分支建议禁止强推与删除，必须通过所列检查；关键 PR 至少一名真实维护者复核。发布 Tag 由受控流程创建，Beta 不进入稳定自动更新通道。使用与项目实际 MSVC/SDK 匹配的固定 Windows 镜像并在日志记录版本；不得只依赖漂移的 windows-latest 名称。

GitHub 建议默认只读令牌、按 job 增加权限、固定完整 Action 提交，并避免让不可信 PR 代码接触特权工作流。来源：GitHub Actions 安全参考。Artifact attestation 用于证明构建来源，不能替代 Windows 发行者签名；权限与验证见 官方证明文档。

单维护者起步：先强制CI和发布清单，由本人审阅后合并/放行，避免配置成无人能够批准自己的PR。加入第二位真实维护者后，再要求独立PR审批与禁止自己批准部署。不要在实际只有一位维护者时声称实现了双人分权。

签名顺序的具体约束：当前Tauri会把Host的bundle标记从UNK补丁为NSS。应先生成各自最终marker的portable/NSIS Host，再分别签名；签名后补丁会破坏签名。冻结并签自有Worker/Engine PE后，使用不再编译、不再改Host的包装入口，最后签Setup。解包后分别验证Host、Worker/Engine与Setup的发行者和时间戳，再重新计算全部清单。第三方原版文件保留其来源与原签名。

当前候选验证器比较unsigned Host大小/marker与Worker原始摘要，不能直接验证签名后不同大小的PE。CI-02需增加签前/签后SHA映射、可信签名及代码身份核对；旧验证器与只验证Host/Setup的签名脚本都需按最终签名流程扩展，并通过实际签名服务POC。

12 · 分阶段执行、发布与回滚

P0 冻结/审计→P1 干净导出→P2 构建/测试→P3 签名/干净机→P4 审阅/Draft→P5 Beta/Stable
  1. P0（当前）：保留所有失败与修复证据；完成这次普通用户完整测试、新候选和 GUI。并行完成源码路径、权属、文档和许可证审计。
  2. P1：用户确认所有者、历史策略、支持范围；补源码导出与文档卫生，在全新目录审阅公开文件。公开仓库前必须 G0/G1 通过。
  3. P2：同步版本号、干净克隆重建、全套验证、固定 payload。CI 分拆可与文档完善并行；所有任务汇合于同一源码/产物清单。
  4. P3：签名与包装按顺序执行；当前 build-desktop.ps1 的 Installer 会重新执行 tauri build，必须先实现只打包已签固定载荷的入口或可靠签名钩子，逐文件证明未被重编译替换。最终签名包在 Win10/11 做原生/安装/回滚验收；QA 不可使用签名前其他二进制替代最终包。
  5. P4：给用户看最终文件、说明、范围、测试证据和 GitHub 可见性决定。批准后建仓/推送已审阅源码；先创建 Draft 并挂齐资产，下载复核。
  6. P5：首发 Beta 标记 Pre-release，稳定通道不自动升级 Beta。收集有复现证据的反馈并补原生语言审校；通过全部 Stable 条件后新版本正式发布。

回滚：不覆盖已发布文件或移动 Tag。出现数据损坏/越权/秘密泄漏立即暂停分发，发布醒目的受影响版本说明和替代下载；保持证据、修复并发布新补丁版本。数据层不做不可逆降级；原包、用户 Vault/设置和任务记录保留。泄漏凭据需要轮换，删历史不能代替轮换。

GitHub 官方建议不可变发行先建 Draft、挂齐资产再发布：发行管理文档。仅在 G6 获准后执行发布命令，使用 --notes-file 保留正文换行，不自动通知任何其他人员。
