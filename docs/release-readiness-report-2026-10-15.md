资源保护范围：这是生产 Worker 的统一硬内存预算和系统余量准入，不是 Host/WebView 或整机内存硬限制。CPU 继续按支持线程参数的引擎分配和原单 Worker 上限控制，不声称有全应用 CPU 硬总量。较高并发或低可用内存时，单 Worker 额度降低，大字典归档可能返回资源不足；可降低并发或释放其他应用内存后重试。瞬时资源探测不保证其他应用之后不会占用内存。

当前自动缓存路由在建立工作区前没有可信头部条目/嵌套数据，因此保持直写；需要中转时可明确选择“总是使用”。本轮不为了自动判断额外增加一次完整归档检查，也不把设置偏好当真实测量。缓存不保证加速。

历史分页降低常态克隆、序列化和传输成本；启动时数据库仍一次性装载任务，内存中的旧历史并未迁出，也没有实现无限历史数据库分页或完整增量协议。所有待处理/待核对/保留工作区的记录仍须传输，不能声称任何队列规模都固定为 20 条。

- 本机人工项：用 Explorer 分别拖入压缩包和包含压缩包的文件夹，核对扫描/确认/取消/加入及内容；补测删除、暂停和取消按钮、DPI/多显示器与键盘操作。跨窗口自动化拒绝仍未核销拖放验收。
- 本机无 CodeSigning 证书；签名工具存在不代表有可用的发行者凭据。真实签名需要用户提供受信任证书或签名服务；不会创建自签证书冒充发行签名。
- 当前为已安装 SDK、开发工具和 WebView2 的 Windows 机器。未发现可直接启动的 Sandbox/干净 VM；Hyper-V 管理查询受权限限制，不能据此认定存在可用测试机。
- 真实桌面验收使用独立 UUID 目录和 `OPENUNPACK_DATA_DIR`，只操作合成归档；它不能代替干净机器、不同 Windows 版本、缺 WebView2 或系统 DPI 验收。
- 当前 C/D 均为正在使用的 NTFS 固定磁盘。本轮不通过填满磁盘、卸载磁盘或切断真实网络制造故障。安全 I/O/配额/取消/恢复回归与真实满盘、拔盘、NAS/SMB 中断分别记录。
- 同机独立审计产品的安装、重复安装、卸载只证明该候选在本机对应流程和合成数据保持；不同版本升级、真实数据迁移与回滚仍需要独立场景。

## 可落地的外部验收步骤

1. 在独立 Windows x64 VM 保存快照，验证未安装 Node/.NET SDK 时启动；分别覆盖已有和缺失 WebView2、标准与离线安装。
2. 安装已冻结的旧版本，用合成归档和本地密码记录建立数据，再升级新候选；核对源包、成品、SQLite/密码库、恢复记录，执行卸载保留数据及快照回滚。
3. 使用有容量上限的专用 VHD 和隔离 SMB 共享，分别执行写满、脱机、连接中断；检查失败分类、原包和已有成品摘要、没有误标完整成功、Worker 全部退出、工作区计量与重启恢复。
4. 在打包流程中完成最终 Host 的 bundle 标记处理，再用正式发行者签名各实际分发 Host 和 Setup，执行 `scripts/verify-release-signatures.ps1` 并指定预期证书指纹，最后冻结所有分发包及 SHA-256。解包后再次检查实际 Host 的签名；本轮针对未签名候选的三字节 bundle 标记归一化比较不能代替签名后核验。签名改变字节后不得沿用未签名摘要。

上述步骤须在可用环境实际执行并保存证据，才可核销对应发布缺口。
